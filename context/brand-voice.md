# Brand Voice

Use this file to capture how the company should sound.

## Visual Representation

- Panosia Connect is an international service (bn is one supported language, not the only audience). Don't default hero/OG image concepts or people depicted to one ethnicity (e.g., South Asian) as if that's the whole audience — vary ethnic/cultural representation across a set of image options rather than treating South Asian as the default look.
- Whatever background is depicted, keep it modest, warm, and dignified per the tone below; never stereotyped or exoticized.

## Tone

- Overall tone: Warm, respectful, trustworthy, and practical — like a thoughtful family advisor, not a dating-app brand
- Level of technical depth: Low. Explain features and processes in plain, everyday language
- How opinionated the writing should be: Moderately opinionated — clearly positioned against anonymous, swipe-style matrimony apps, without attacking competitors by name
- What the brand should feel like: Serious about marriage as an institution; accountable; calm; family-friendly; founder-led — plain, confident, mission-driven ("access to serious matrimony should not be gated by payment")

## Writing Preferences

- Paragraph style: Short paragraphs, scannable, concrete
- Sentence style: Clear and direct; plain words over jargon
- CTA style: Invitational and low-pressure (create a profile, start your network, request verification) — tied to the next logical step, not hype
- Jargon guidance: Avoid industry jargon; define product terms (Connector, Candidate, Digital ID Verification) in plain language
- Things to avoid: Hype and guarantees, pressure tactics, swipe-culture references, sarcasm, anything casual or flippant about marriage

## Vocabulary

- Preferred terms: Candidate, Connector, trusted introduction, network, verification, privacy controls, intentional, biodata, reference / "be a reference for" (2026-08-26: prefer over "vouch"/"vouching", it's the app's own current term, `Verification References`, `Be a Reference`, per its live homepage copy, and more globally familiar to non-native English readers than the more idiomatic "vouch"; "vouch for" is fine as an occasional natural-language gloss, not the primary term)
- Terms to avoid: Dating, swiping, "matches" described as auto-generated (unless explaining what we don't do), soulmate-type promises, "vouch"/"vouching" as the primary term (see reference, above)
- Verification requirement framing (2026-08-26, confirmed product fact; softened 2026-09-12): without any ID verification, a user can still create a profile, use Profile Import, control privacy, share their own profile (Public View and Private View), and export it to PDF — none of that needs verification, and that's the claim to keep front and center. Level 1 ID Verification is a real gate before a Candidate can interact with other users: searching, using Discover, requesting someone else's Private View, or chatting, per `context/site-profile.md`'s Product Features section. Don't omit that gate or imply full interaction is free, but it doesn't need to be stated with a hard "required"/"mandatory" every time — a softer, natural mention of the gate (e.g. "before you can message someone, a quick ID check is needed") is fine as long as the fact itself comes through. Only avoid "required"/"mandatory" when the sentence is about creating, managing, or sharing your own profile, where it stays genuinely optional. Levels 2 and 3 remain fully optional regardless of Level 1 status.
- Product naming conventions: "Panosia Connect"; roles capitalized (Candidate, Connector); verification levels referenced as Level-1/2/3; feature names such as "Digital ID Verification" treated as proper nouns

## Proof Style

- What kinds of evidence are acceptable: Platform features and mechanics (verification process, privacy controls, relationship labels); brand first-person posts ("why we built this"); clearly illustrative example personas (e.g., Ryan and Sarah) for explanation
- Whether to use first-person experience: Yes, in brand voice — "why we created Panosia Connect" style posts are on-brand
- Whether fictional examples are allowed: Yes, clearly illustrative personas are fine
- Statistical claims: Only with user-provided data; never invent numbers

## Messaging Priorities

- Core themes to emphasize: Trust before matches; family and community are part of the process; privacy stays in the user's control; verification reduces risk; free to join with no subscriptions — access to opportunity is not the product; serious lifelong commitment only, not casual dating
- Important caveats to acknowledge: Verification reduces but cannot guarantee against fraud; no platform can guarantee a match; the online process still depends on real-world judgment; Level 1 ID Verification is optional and paid to join or create a profile, but is genuinely required before a Candidate can search, use Discover, request Private View, or chat (see Vocabulary's verification requirement framing note) — state that gate honestly rather than implying full interaction is available pre-verification
- Claims to avoid unless supported: Success rates, user counts, fraud-reduction statistics, absolute "safe/safest" claims, invented conversion stats (existing site copy mentions "3x more profile responses" for background checks — reuse only that wording, don't invent new numbers)
